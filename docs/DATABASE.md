# Original PostgreSQL model

The schema and migrations are owned by the foundation implementation. Ent code is
generated by one owner. Other modules may issue parameterized SQL through the
shared `database.DBTX`; they must not change generated files or run Ent generation.
Migration application is explicit via `cmd/migrate`; API startup never migrates.

All tables have UUID `id`, `created_at`, `updated_at`, nullable `deleted_at`.
Unless stated otherwise IDs below are UUIDs; JSON fields are JSONB; timestamps are
timezone-aware. Foreign keys enforce ownership, while services additionally check
workspace/project scope before accepting related IDs. Every mutable domain query
must filter soft deletion. Table names and columns below are the SQL contract.

Natural identifiers and memberships use partial unique indexes where
`deleted_at IS NULL`. `projects.next_sequence` is updated under a row lock in the
same transaction that creates the corresponding work item. Work items additionally
have unique `(project_id,sequence_id)`. This sequence is never reused.

State `group_name`: backlog, unstarted, started, completed, cancelled.
Work-item `priority`: none, low, medium, high, urgent. Module status: backlog, planned,
in-progress, paused, completed, cancelled. Intake status: pending, accepted,
rejected, duplicate, snoozed. Roles: 5/15/20. The services enforce valid values;
the migration additionally installs checks for critical enum and role columns.

New schema requests go to the foundation owner before a domain module relies on
the new field. This document is the common contract for parallel implementation.

Migration 0005 adds `projects.estimate_id` for the active scheme and
`work_items.estimate_point_id` for a chosen point. The existing `work_items.estimate`
remains the numeric projection; category choices have a null numeric value.

Migration 0006 adds module links with a full workspace/project/module foreign key
and saved workspace analyses. Saved analysis names are unique among live rows in
one workspace; execution uses the requesting user's current data visibility.

Migration 0007 adds the nullable internal cycle transfer progress snapshot. It is
excluded from ordinary cycle serialization and writable only by the transfer
workflow. Progress reads apply the current actor's visibility before aggregating
captured items; raw snapshot content is never returned.

Migration 0008 adds `projects.guest_can_view_all` with a false default. Project
policy returns it as `identity.Scope.GuestCanViewAll` separately from `Role`; the
setting changes Guest read visibility, never membership or write privileges.

`projects.settings.features` stores partial booleans for cycles, modules, pages,
views and intake (omitted values are enabled); `settings.cover_image_url` stores
the optional cover URL. Generic project settings merge objects without replacing
independently managed automation configuration. Estimate and automation mutations
use their owning domain routes.

`users.preferences._last_visited` stores nullable workspace/project UUIDs and is
owned by the navigation endpoint. Its response rechecks current access. Other
preference patches preserve this value.

Workspace notification preferences are `preferences(scope='notifications',
workspace_id=<workspace>,project_id=NULL,user_id=<recipient>)`. Notification
`data.reasons` lists mentions, assigned, subscribed or created; `data.silent=true`
marks rows retained for email when in-app delivery is disabled. Email outbox events
reference the notification UUID and never snapshot its title, body or recipient.
