## 2. 技术方案

| 层 | 决定 |
| --- | --- |
| 主站 | React + TypeScript + Vite + React Router，SPA |
| 实例管理 | 原创 React 页面，与主站共享原创设计系统 |
| 公开分享 | 原创 React 公开页面，当前实现为 SPA，包含匿名读取和独立公开互动 |
| UI | Tailwind CSS + Radix/shadcn/ui，独立设计 token、组件、文案与资源 |
| 状态 | MobX；任务实体与各视图 ID/分组/分页索引分离 |
| 表格、拖拽 | TanStack Table/Virtual、Pragmatic Drag and Drop |
| 编辑器 | Tiptap；文档协作 Yjs + Hocuspocus |
| API | Go + Gin；Ent 管理关系模型；PostgreSQL |
| AI | 用户指定配置的 OpenAI Responses 接口，模型 `gpt-5.6-terra` |
| 异步 | Redis + Asynq；worker 与 API 共享领域代码 |
| 附件 | S3 兼容存储及鉴权上传/下载 |
| 部署 | Docker Compose + Caddy；不依赖原 Django 服务 |
| 验证 | Go/真实 PostgreSQL 集成、前端类型/单元测试、Playwright 浏览器、视觉对照 |

前端、业务 API 与协作适配代码全部原创。视觉参照体现为布局密度、信息层级、
中性色调、边框、交互反馈与多主题等产品表现，不复用 Plane 的表达或品牌资源。
工作项实体、关系、权限和协作行为按功能规格重新设计。

已确认决策：用户明确“不需要兼容”。API、数据库和客户端协议独立设计，不增加
Plane 历史接口、数据库或数据迁移兼容层。开放 API 本身作为产品功能仍在范围内。
统一契约位于 `docs/API_CONTRACT.md`，数据库结构位于 `docs/DATABASE.md`。

## 4. 验收规则

1. API 的授权、字段、错误、事务、排序分页和副作用属于功能契约。
2. 服务端必须拒绝跨 workspace/project 的关联写入与资源读取。
3. 列表、看板、详情、周期、模块间的同一工作项保持一致；失败可回滚。
4. 文档以可恢复协作状态持久化，不能只保存展示 HTML。
5. 任务队列持久化，失败可重试，重复执行不会重复产生业务副作用。
6. 主站、管理站、公开站均进入浏览器验证范围；浅色/深色、侧栏、列表、看板、
   详情、编辑器、弹窗与设置进行固定视口视觉对照。
7. 不能以 HTTP 200 空对象、占位按钮、构建成功、依赖安装成功认定功能完成。
8. 未取得实际证据时使用“未验证”，有已知缺口时使用“未完成”。
